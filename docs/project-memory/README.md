# Project memory — exported

These are the notes Claude keeps about this project between sessions. They live
in the Claude desktop app's own store, which is **local to one machine** — they
do not travel with the repository, and they were not in the git history until
this export (5 September 2026).

Exported so the reasoning survives a machine move. `MEMORY.md` is the index.

**They are a snapshot, not the live copy.** If Claude updates its memory on a
machine, this folder goes stale until someone re-exports. Treat
`PROGRESS_TRACKER.md` §3 as the authoritative record of what happened and why —
these notes are the distilled *rules* drawn from it, written for whoever picks
the project up next.

Roughly what each kind covers:

- **The measurement model** — the vulnerability formula, the hazard construct
  split, unweighted variables. These are closed decisions. The files say so
  explicitly because the model moved three times in eight days and re-arguing it
  is the most expensive mistake available.
- **The data** — the DS-division register's volatility, the upload templates,
  Central's loaded dataset, how a returned expert review is folded back in.
- **The build** — the Stage 4 engine, the results API and map, the import tab,
  and the database replica recipe.
- **The traps** — what has already gone wrong and how it was caught. Most were
  invisible to reading and obvious the moment something ran.
